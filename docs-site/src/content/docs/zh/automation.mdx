## 结构化输出

```bash
emoera search "发布回滚" --json
emoera ask "列出发布风险" --json
emoera ask "逐步检查" --jsonl
```

JSON 适合一次性消费最终结果；JSONL 适合持续处理流式事件。自动化程序应解析字段，不要依赖彩色终端文本。

## 请求追踪与幂等

```bash
emoera --request-id "deploy-audit-20260728-001" \
  ask "检查发布风险并给出回滚建议" --json --no-color
```

请求 ID 便于把 CLI 调用与服务端日志关联。重试上传或写入操作时，应复用幂等键，避免重复执行。

## 退出码

| 退出码 | 含义 |
| --- | --- |
| `0` | 成功 |
| `1` | 一般运行错误 |
| `2` | 参数或配置错误 |
| `3` | 未认证或 Token 无效 |
| `4` | 无权限 |
| `5` | 资源不存在 |
| `6` | 超过速率或用量限制 |
| `7` | 网络或服务暂不可用 |

## Agent 调用原则

1. 为每个 Agent 创建独立、最小权限 Token。
2. 设置超时，并只对可重试错误做指数退避。
3. 保存 `requestId`，不要把 Token 或完整私有文档写进日志。
4. 在执行写操作前，先用只读命令确认目标组织和文档范围。
